## (3) THE ARCHITECTURE — decided

### 3.1 The lookup chain (final)

```
S1  exact NUTRI_INDEX[name]
S2  de-plural  name.replace(/s$/,'')
S3  fuzzy      — name.length>=3, candidates length>=3, thr = len<=5 ? 1 : 2
                 canonical tie at best distance  →  AMBIGUOUS  →  ask-back
S4  substring  — longest whole-word alias, BOTH directions (keep reverse containment)
S5  head-noun fuzzy — same rules as S3
```

**Thresholds are settled and I am closing the argument on them.** Keep `thr = len<=5 ? 1 : 2`. **Reject** the relative-distance rule `bd < len/2` (measured −6pp resolve for nothing). **Reject** killing reverse containment (measured: loses 5 real English resolutions, gains 0). **Adopt** the length floor of 3 — it costs 0.5pp of English resolve and is the *only* thing that defuses the 1–2-character magnet class, killing `sárgarépa`→peanut butter (588 kcal vs a true ~41) outright.

**Tie handling, measured with correct canonical-tie detection:** ask-on-tie costs **0.2pp** of resolve, converts **0.6pp** of wrong foods into questions, and **in 100% of asks the correct answer is among the offered options**. (My first sweep said 3.2pp; that was my own bug — I was counting alias ties, not canonical ties. Corrected.) Adopt it.

### 3.2 Accent folding — the exact table

`normTerm` (`index.html:5113`) is replaced. **This is stage C1's `_fold`, landing in `normTerm` itself so the food path, the meal matcher and the allergen filter all inherit it — they are one problem (§6).**

```js
function normTerm(s){
  s = String(s||'').normalize('NFC').toLowerCase();
  var DI = { 'ß':'ss', 'æ':'ae', 'ø':'oe', 'å':'aa', 'ä':'ae', 'ö':'oe',
             'ü':'ue', 'œ':'oe', 'đ':'d', 'ð':'d', 'þ':'th', 'ł':'l', 'ı':'i' };
  s = s.replace(/[ßæøåäöüœđðþłı]/g, function(c){ return DI[c]; });
  s = s.normalize('NFD').replace(/[\u0300-\u036f]/g, '');   // é á í ó ú ő ű ç ñ â è ê
  return s.replace(/[^a-z0-9 ]+/g, ' ').replace(/\s+/g, ' ').trim();
}
```

`NFC` first so decomposed keyboard input folds identically — I verified every row below against **both** precomposed and NFD input and they agree:

`æg`→`aeg` · `mælk`→`maelk` · `øl`/`Öl`→`oel` · `ägg`→`aegg` · `mjölk`→`mjoelk` · `Hähnchen`→`haehnchen` · `Straße`→`strasse` · `œuf`→`oeuf` · `sárgarépa`→`sargarepa` · `főzelék`→`fozelek` · `rugbrød`→`rugbroed` · `knäckebröd`→`knaeckebroed` · `niçoise`→`nicoise` · `purée`→`puree`

**English is byte-identical.** `chicken breast`, `olive oil`, `2 eggs`, `peanut butter` all unchanged.

**Keys shorter than 3 characters, before vs after:** `normTerm` produces **5** (`g`, `l`, `gg`, `ei`, `uf`); the fold produces **1** (`ei`, German egg). Combined with the S3 length floor, the magnet class is closed.

**What the fold fixes on its own, today, in English:** `pur` and `oise` leave `FOOD_VOCAB`; `puree` and `nicoise` enter it; `fuzzyCorrect('pure')` goes `'pur'`→`'puree'` and `fuzzyCorrect('noise')` goes `'oise'`→`null`. **This is a shipped English defect, and it reframes the fold's justification to Osefe: it is not a multilingual feature, it is a bug fix that also unlocks multilingual.**

```
tf('{n} items were not recognised.', {n:n})
t('Nothing here was recognised. Logged at 0 kcal.')
t('Not recognised — logged at 0 kcal.')
t('Your saved words are full. Remove one to add another.')
```

**Register.** I endorse the Ask-Back seat's wording and his reasoning for it. *"Not in the food list"* locates the gap in **our** table, not in the user's typing; it is a statement of fact followed by a question the buttons answer. Rejected: *"Sorry, I don't recognise that"* (apologetic), *"Unknown food"* (reads as an error code and blames the input), anything with an exclamation mark.

**Trap, verified:** `renderToday` (`index.html:8121`) declares `var t={kcal:0,…}` at **`:8122`**, shadowing the translator for the whole function. Any `t('…')` added there is a `TypeError`. Use `tf()` inside `renderToday`; `renderHistory` does not shadow and may use `t()` freely.

### 4.4 The unresolved chunk — ruled

**It is logged, as an explicitly flagged zero, and it does not buy a streak.**

Not logging it silently discards text the user typed — deleting a Dane's dinner because our parser is English is the same disease pointed the other way, and there is no manual-entry path in the Food tab (`#foodText` `:2257` + `#foodAdd` `:2266` is the entire input surface; `addEntry` `:8105-8119` has no kcal field). A draft-state alternative adds persistence that must survive reload, autosave, quota exhaustion and import — new failure surface on a phone to solve what the flagged entry already solves.

Concretely:
- **(a)** `:8058` keeps `matched:false`, routed through `FT` (§3.6).
- **(b)** entry gains `unres:<count>`, persisted, exported, sanitised via `_inum`.
- **(c)** `:8117` — colour is `var(--amber)`, **not** `var(--lime)`, when text was typed and **zero** chunks matched. Mixed keeps lime.
- **(d)** `:8115` — suppress the `logChange`→`__bumpStreak` (`:2876`→`:2879`, `:2885-2894`) when text was typed **and** `items.length > 0` **and** matched-count is 0. **Guard on matched-count, never on `total.kcal === 0`** — black coffee is a legitimate zero-calorie log and a photo-only entry must still count.
- **(e)** history row: `t('Not recognised — logged at 0 kcal.')`, in `renderHistory`.
- **(f)** `renderToday`'s badge (`:8127`) currently reads "1 logged" while the note below simultaneously reads "Add a meal above to start today's log." Fix the contradiction in the same commit.

**(c) and (d) are correctness, not preference, and I rule them so:** a green "Added" toast and a live streak on an entry that recorded nothing is precisely the "the app affirms success" failure Osefe reported. But **(d) is user-visible in the streak counter and must appear in the release note.**

### 4.5 Per-user learned aliases — **APPROVED**

The justification is the 37.6% figure: **283 of 753 of our own English meal ingredients don't resolve** (`lamb`, `duck`, `kale`, `cauliflower`, `mango`, `halloumi`…). An offline product with a fixed 87-concept table cannot be completed by any lexicon in any number of languages — only by the user. And it costs zero recurring money, which is the cost rule pointing the same way.

```
STATE.foodLex = { a: { "<folded surface>": "<canonical NUTRI_DB key>" },
                  c: { "<folded surface>": {k:,p:,c:,f:,g:} } }
```
- **Top-level on `STATE`, not in `prefs`** — `prefs` is `Object.assign`-merged on import (`:7196`), which would blend a stranger's lexicon into the user's. `foodLog`-style wholesale replacement is what we want.
- **Consulted at S0** of `findFood`, exact folded match only.
- **HARD RULE: user strings never enter `NUTRI_KEYS` and are never fuzzy candidates.** A user who teaches `huel` must not thereby create a magnet for `fuel`. One line, load-bearing.
- **Export:** add to the explicit field list at `:7126` or it is invisible to backup.
- **Sanitise** in `_sanitizeIngested` (`:7139`): keys through `normTerm`'s own charset, `slice(0,32)`, drop `<2`. **`.a` values must satisfy `NUTRI_DB[v]` or be dropped** — a whitelist of 87 developer-authored ASCII strings, strictly stronger than `_sid`'s charset coercion. `.c` values `_inum` then clamp: `k` 0–900 (pure fat is 884), `p/c/f` 0–100, `g` 1–2000. Caps 200 `.a` / 50 `.c` ≈ 6.8 KB = 0.33% of the file.
- **At the cap, refuse with a message; no silent LRU eviction.** Silently discarding a word the user taught is the failure mode this council exists to end.
- **`esc()` everything at render anyway.** Belt and braces is this file's convention and costs nothing.

### What CANNOT be automated — and the Malay problem

**This is the hardest thing in this document and I will not pretend otherwise.**

A lexicon entry that maps a real word to the **wrong** canonical food is **invisible to every gate we own**. `green.js` passes. `MISSING: 0` passes — it counts keys, not meanings. A resolve-rate test passes, because the word *resolved*. The only detector is a human who reads the language. That is exactly how Malay `blnnth` shipped past a MISSING:0 and a GREEN.

**And it is worse here than it was there**, because this feeds calorie arithmetic. A wrong UI string is embarrassing. `sárgarépa` → peanut butter is **588 kcal against a true ~41** — a 14× overcount, `matched:true`, green toast, no warning, compounding every meal, every day, in a paid product whose entire value proposition is an accurate private log. **A plausible wrong alias is strictly worse than a gap**, and the gap is the safe default. My own authored lexicon proves the risk is not theoretical: 9 of 140 entries pointed at foods that don't exist in `NUTRI_DB` — and those were the *lucky* errors, because they crash loudly instead of lying quietly.

**Six controls, in force order:**

1. **Every lexicon entry carries an English gloss in the source.** `'kylling': 'chicken breast', // da: chicken`. Non-negotiable — an ungloassed entry is unreviewable by anyone on this team.
2. **Committed per-language core-40 truth list, authored separately from the lexicon, by a different pass.** If the same person writes the lexicon and its expected outputs, the test proves only self-consistency.
3. **Sanity range assertion — cheap, automatable, and catches the worst class.** Assert every lexicon entry's target kcal/100 g is within a plausible band for its food *category* as declared in the gloss. `sárgarépa`(vegetable)→588 kcal fails; `ost`(dairy)→389 kcal-with-66 g-carbs fails on macro shape. This would have caught 4 of the 9 measured wrong matches without any language knowledge.
4. **Macro-profile divergence check.** `ost`→oats has kcal within 4% (389 vs 402) but **+64.7 g carbs and −26 g fat per 100 g**. kcal alone hides it; the macro vector does not. Automatable.
5. **Round-trip review: gloss → back-translate → compare.** Mechanical, catches transposition and copy-paste drift, does not catch a genuine misunderstanding.
6. **Native review of the lexicon diff — and this one is not optional.** Danish is Osefe's own market and he can read it. For es/de/sv/nb/hu/fr we have no native reader on the team, and **I am recording that as an accepted, unmitigated risk** rather than pretending controls 1–5 close it. **Ship each language's lexicon behind its own commit** so a single language can be reverted without taking the other six with it. That is the real mitigation: not prevention, but a one-commit blast radius.

**One more thing that cannot be automated.** Two runtime bugs this year — the calendar `var t` shadow and the media-log render-on-load — passed every suite and were caught only by loading the app. `renderToday` at `:8122` has **the same `var t` shadow**, and F4 adds strings into that neighbourhood. **A browser load of the Food tab, in Danish, typing `kylling og ris`, is a required sign-off artifact for F4.** Not a suite. A human, on a device.
